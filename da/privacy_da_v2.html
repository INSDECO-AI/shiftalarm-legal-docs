ShiftAlarms privatlivspolitik

Version 2. Dato: 29.06.2026.

1. Generelt princip for databehandling

ShiftAlarm følger primært en offline-first-model. Centrale brugerdata oprettes, behandles og lagres lokalt på brugerens enhed. Udvikleren modtager ikke automatisk sådanne data, medmindre brugeren sender dem via en supporthenvendelse, eksport, e-mail, beskedtjeneste, cloudlager, appbutik eller en anden metode, som brugeren vælger.

I denne version anvender appen ikke annoncenetværk, eget kontosystem, serverbaseret godkendelse, Firebase Analytics, Google Analytics, Crashlytics eller AdMob, medmindre dette udtrykkeligt angives i en opdateret version af denne politik.

2. Data, der kan lagres lokalt

Afhængigt af de anvendte funktioner kan appen lagre følgende data på enheden:

  • appindstillinger, sprog, tema, widgetindstillinger og brugerpræferencer;
  • almindelige alarmer, vagttilknyttede alarmer, tidspunkt, gentagelser, lyde, vibration, udsættelse, gradvis lydstyrke og tilknyttede indstillinger;
  • vagtplaner, vagtskabeloner, kalenderændringer, fridage og brugerens markeringer;
  • Stedsalarmer: koordinater, radius, hændelsestype for indgang/udgang, adresse, stednavn, gemte steder, tidsplan og udløsningstilstand;
  • noter, begivenheder, påmindelser, tjeklister, tekstblokke og tilknyttede datoer;
  • lydnoter, stemmeoptagelser og teksttransskriptioner;
  • timer, stopur, verdensure og historik over visse handlinger, når en sådan historik indgår i funktionen;
  • indstillinger for lønberegning, bonusser, fradrag, sanktioner, rapporter og tilknyttede beregninger;
  • diagnostiklogfiler, tekniske hændelser, tilladelsesstatus, fejl og funktionstilstande;
  • sikkerhedskopier, hvis brugeren opretter dem manuelt.

3. Data, som brugeren kan sende til udvikleren

Hvis brugeren kontakter support på support@insdeco.ru, kan udvikleren modtage brugerens e-mailadresse, navn eller e-mailsignatur, meddelelsestekst, vedhæftede filer, skærmbilleder, sikkerhedskopifiler, diagnostikrapporter, enhedsmodel, Android-version, appversion, hændelsestidspunkt og beskrivelse af problemet.

Sådanne data sendes kun ved brugerens handling. Brugeren bør gennemgå e-mailen og de vedhæftede filer, før de sendes.

4. Formål med behandlingen

Data anvendes til at drive appens funktioner, gemme brugerindstillinger, levere alarmer og påmindelser, drive Stedsalarmer, vise noter og widgets, oprette sikkerhedskopier, diagnosticere fejl, behandle supporthenvendelser, forbedre appens stabilitet, overholde retlige krav og beskytte udviklerens og brugerens rettigheder.

Afhængigt af gældende ret kan behandlingsgrundlaget omfatte opfyldelse af aftalen med brugeren, brugerens handling, samtykke til bestemte tilladelser, legitim interesse i support og sikkerhed samt overholdelse af retlige forpligtelser.

5. Enhedstilladelser

Appen kan kun anmode om de tilladelser, der kræves til de relevante funktioner:

  • notifikationer — til alarmer, timere, påmindelser og tjenestenotifikationer;
  • præcise alarmer og alarmtilladelser — for at udløse på det tidspunkt, brugeren har valgt;
  • placering, mens appen bruges — til valg af steder, kort og opsætning af Stedsalarmer;
  • placering i baggrunden — til Stedsalarmer, når appen ikke er åben;
  • mikrofon — til lydnoter, stemmeinput og talegenkendelse;
  • internet — til download af sprogpakker, juridiske dokumenter, hjælp, vejledninger, offline-modeller til transskription, kort og netværksfunktioner;
  • filadgang via systemets filvælger — til eksport og import af sikkerhedskopier;
  • indstillinger for batteri og baggrundsaktivitet — for at forbedre pålideligheden af alarmer, notifikationer og Stedsalarmer.

Brugeren kan tilbagekalde tilladelser i Android-indstillingerne. Efter tilbagekaldelse kan visse funktioner blive utilgængelige eller virke begrænset.

6. Placering og kort

Placeringsdata bruges til at vælge et punkt på et kort, gemme Stedsalarmer, registrere indgang i eller udgang fra et afgrænset område, vise en adresse og oprette gemte steder. Koordinater og indstillinger for Stedsalarmer lagres lokalt på enheden, medmindre brugeren eksporterer eller sender dem.

Når brugeren anvender kort eller adressesøgning, kan appen kontakte kort- og geokodningskomponenter, herunder osmdroid/OpenStreetMap, Nominatim til omvendt geokodning, Android-systemets Geocoder eller en anden tjeneste, der er tilgængelig på enheden. Sådanne tjenester kan modtage tekniske forespørgselsdata, IP-adresse, koordinater eller andre data, der er nødvendige for at vise kortet eller bestemme en adresse.

7. Lyd samt offline- og onlinetransskription

Lydnoter og transskriptioner oprettes ved brugerens handling og kan indeholde personoplysninger eller følsomme oplysninger, hvis brugeren optager dem. De lagres lokalt på enheden, medmindre brugeren eksporterer eller sender dem.

Offlinetransskription kan anvende talegenkendelsesmodeller, der er downloadet lokalt. Når sådanne modeller downloades, kan den eksterne server se tekniske forbindelsesdata såsom IP-adresse og oplysninger om forespørgslen.

Onlinetalegenkendelse kan anvende Android-systemets talegenkendelsestjeneste, som er valgt af enheden, producenten, brugeren eller operativsystemet. I så fald kan lyddata og tekniske oplysninger blive sendt til og behandlet af den valgte talegenkendelsestjeneste efter dens egne regler. Udvikleren af ShiftAlarm kontrollerer ikke politikkerne for denne systemtjeneste.

8. Netværksdownloads og eksterne kilder

Appen kan bruge internettet til at downloade sprogpakker, manifestfiler, juridiske dokumenter, hjælpemateriale, vejledninger og offline-modeller til transskription, herunder fra GitHub eller en anden ekstern kilde, der er angivet i appen. Ved sådanne forespørgsler kan den eksterne server modtage IP-adressen, dato og klokkeslæt for forespørgslen, filsti, forbindelsesoplysninger og andre almindelige tekniske data.

Filer, som appen har implementeret integritetskontrol for, kan kontrolleres med SHA-256 eller en anden kontrolsum. Dette mindsker risikoen for filbeskadigelse, men garanterer ikke, at den eksterne kilde er tilgængelig.

9. Appbutikker og betalinger

Appen købes gennem en appbutik, for eksempel RuStore eller Google Play, hvis appen er tilgængelig på den relevante platform. Appbutikken behandler selvstændigt brugerens konto, betalinger, tilbagebetalinger, købshistorik, installation og opdateringer efter sine egne regler og sin egen privatlivspolitik.

Udvikleren modtager ikke bankkort, betalingsadgangskoder eller fuldstændige betalingsoplysninger, når betalingen sker gennem appbutikken.

10. Sikkerhedskopier og eksport

Sikkerhedskopier oprettes kun ved brugerens handling. En sikkerhedskopifil kan indeholde en væsentlig del af appens lokale data, herunder alarmer, vagtplaner, noter, geografiske punkter, indstillinger, diagnostik og andre oplysninger.

Hvis brugeren gemmer eller deler en sikkerhedskopi via en anden app, cloudlager, e-mail, beskedtjeneste, filhåndtering eller eksternt lager, afhænger den videre beskyttelse og behandling af filen af den lagrings- eller overførselsmetode, som brugeren har valgt.

11. Diagnostik

Diagnostiklogfiler er beregnet til fejlfinding og kontrol af funktioner. De kan indeholde tekniske oplysninger om apphændelser, tid, tilladelser, enhed, OS-version, appversion, alarmtilstand, tilstand for Stedsalarmer, noter, sikkerhedskopier og fejl.

Diagnostik lagres lokalt, indtil brugeren rydder den eller manuelt sender den til udvikleren.

12. Videregivelse til tredjeparter

Udvikleren sælger ikke brugerdata til annoncører og overfører ikke automatisk lokale appdata til tredjeparter. Data kan blive overført, hvis brugeren anvender eksterne tjenester, sender en supporthenvendelse, eksporterer en sikkerhedskopi, anvender kort, geokodning, onlinetalegenkendelse, en appbutik eller en anden ekstern tjeneste.

Tredjepartstjenester behandler data efter deres egne regler. Brugeren opfordres til at gennemgå politikkerne for den valgte appbutik, e-mailtjeneste, cloudlager, korttjeneste, talegenkendelsestjeneste og andre eksterne tjenester.

13. Opbevaringsperiode

Lokale data opbevares på enheden, indtil brugeren sletter dem i appen, rydder appdata, afinstallerer appen, gendanner data fra en anden sikkerhedskopi eller sletter sikkerhedskopifilen fra den valgte lagerplacering.

Supporthenvendelser, e-mails, vedhæftede filer og diagnostikmateriale, som brugeren sender til udvikleren, kan opbevares uden en på forhånd fastsat udløbsdato for at bevare supporthistorik, analysere tilbagevendende problemer, beskytte rettigheder og overholde retlige forpligtelser. Brugeren kan anmode om sletning af sådanne data; anmodningen efterkommes, medmindre fortsat opbevaring kræves eller er tilladt efter gældende ret.

14. Sikkerhed

Appen anvender almindelige Android-mekanismer, herunder operativsystemets isolering af appdata, systemtilladelser og systemets filvælger. Visse downloadede filer kan kontrolleres med en kontrolsum, hvis en sådan kontrol er implementeret for den pågældende filtype.

Brugeren er ansvarlig for at beskytte enheden, skærmlåsen, adgangen til e-mail, cloudtjenester, sikkerhedskopier og eksternt lager. Sikkerhedskopier og eksporterede filer kan være tilgængelige for andre, hvis brugeren opbevarer dem et ubeskyttet sted eller deler dem med tredjeparter.

15. Lande, hvor behandling kan finde sted

Lokale data forbliver på brugerens enhed i det land, hvor enheden bruges. Data, der overføres gennem appbutikker, GitHub, korttjenester, talegenkendelsestjenester, e-mailtjenester, cloudtjenester og andre eksterne tjenester, kan behandles i de lande, hvor disse tjenester drives eller har infrastruktur.

Data, der sendes til udviklerens support, kan behandles dér, hvor udvikleren og udviklerens e-mail-, hosting- eller sikkerhedskopitjenester er placeret.

16. Brugerens rettigheder

Brugeren kan se, ændre og slette de fleste data direkte i appen. Brugeren kan også rydde appdata via Android, afinstallere appen, tilbagekalde tilladelser, eksportere en sikkerhedskopi eller slette sikkerhedskopifiler, som brugeren har oprettet.

For data, der er sendt til udvikleren, kan brugeren kontakte support@insdeco.ru og anmode om indsigt, berigtigelse, sletning, begrænsning af behandling eller tilbagekaldelse af samtykke, hvor sådanne rettigheder følger af lovgivningen. For at beskytte data kan udvikleren anmode om oplysninger, der er nødvendige for at kontrollere, at anmodningen vedrører den relevante bruger eller e-mailadresse.

Hvis brugeren befinder sig i en jurisdiktion, der giver ret til at klage til en databeskyttelsesmyndighed, kan brugeren kontakte den kompetente myndighed efter gældende ret, herunder Datatilsynet i Danmark, når det er den relevante tilsynsmyndighed.

17. Børn

Appen kan være aldersmærket 0+, men den er ikke beregnet til, at udvikleren målrettet indsamler børns personoplysninger. Hvis et barn bruger appen, bør en forælder eller værge føre tilsyn med indstillinger, tilladelser, noter, lydoptagelser, geografiske punkter, sikkerhedskopier og supporthenvendelser, når dette kræves efter lovgivningen eller familiens regler.

18. Ændringer af denne politik

Udvikleren kan opdatere denne politik. Den aktuelle version kan leveres sammen med appen, downloades fra en ekstern kilde eller åbnes fra en medfølgende reserveversion. Ved væsentlige ændringer kan appen anmode brugeren om at gennemgå eller acceptere det opdaterede dokument, hvis dette kræves efter lovgivningen eller appens logik.
